### P-SEA-DOTS — Titik event di peta kartu Recent Seismic Activity
- **Temuan** (laporan owner, 2026-09-09, screenshot Warning → SEE DETAILS): peta mini di kartu "Recent Seismic Activity" hanya basemap gelap + label kota (Bogor, Bandung, dst), tanpa titik. Kartu menyebut "6 events" tetapi peta tidak menunjukkan di mana event itu terjadi.
- **Status kini (terverifikasi di kode)**:
  - `RecentSeismicActivity` (`ui/warning/WarningUiState.kt:109`) hanya membawa agregat: `eventCount`, `mostRecent`, `strongest`, + lat/lon perangkat. Tidak ada koordinat per event.
  - `fetchRecentActivity` (`ui/warning/WarningViewModel.kt:363`) sudah memegang `events` dari `fetchEvents` (radius 200 km, 30 hari) tetapi membuang koordinat; hanya agregat yang disimpan.
  - `RecentSeismicActivityCard` (`ui/warning/WarningComponents.kt:491`) memanggil `QuakeMap` tanpa `markers` (komentar: "this card draws no overlays of its own").
  - `QuakeMap` (`ui/common/QuakeMap.kt:159`) sudah mendukung `markers: List<MapMarker>` (MapLibre circle layer) — dipakai kartu lain, tinggal diumpan.
- **Arah rencana (belum audit, belum ada nomor D)**: tambah daftar titik per event (lat/lon + intensitas, dibatasi N + penanda cap) ke model; teruskan sebagai `markers` ke `QuakeMap`; gaya dot mengikuti skala intensitas yang sudah ada; kasus 0 event / offline / tanpa posisi tetap tanpa titik palsu (prinsip kartu ini: tidak menemukan angka).
- **Audit Hermes 2026-09-09 (terverifikasi di kode)**:
  1. Data sudah di tangan: `EarthquakeEvent` membawa lat/lon centroid + `pgaGal`/`mmi`/`intensityLabel`; `fetchRecentActivity` memegang ≤100 event (`ACTIVITY_PAGE_LIMIT=100`) — tanpa request baru, tinggal teruskan.
  2. `MapMarkerKind` hanya mengenal STATION_OFFLINE/ONLINE, SELECTED, USER — perlu kind baru EVENT dengan warna beda dari station agar tidak tertukar. Satu warna dulu (bukan gradasi intensitas) supaya kecil dan mudah direview.
  3. Kejujuran cap: dots = tepat events yang mendasari count (satu halaman). Jika penuh, count sudah bertulis "100+" sehingga "+"-nya mencakup keterbatasan dots — tanpa string baru. Tiap dot = event tercatat asli, tidak ada yang difabrikasi.
  4. Kasus 0 event/offline/tanpa posisi: tanpa dots (tidak ada yang bisa diplot jujur); perilaku honest-empty existing tidak berubah. Dots statis per bukaan kartu, sama seperti statistiknya.
  5. Preseden lapisan: `SensorsUiState:217` sudah membangun `MapMarker` di UiState — `RecentSeismicActivity.dots: List<MapMarker>` dapat diterima. Tidak seperti D-021/D-022, mapping ini murni → unit-testable JVM.
- **D-024 (DISETUJUI owner 2026-09-09, tercatat di `docs/DECISIONS.md`)**: "RecentSeismicActivity membawa events yang diplot; kartu menggambar satu dot per counted event (kind EVENT, warna beda dari station)." Verifikasi: unit test mapping + cap; cek visual (6 event → 6 dot di radius; 0 event → peta bersih); suite unit + lint hijau.
- **Syarat lanjut**: implementasi oleh OpenCode.

### P-NOTIF-SYNC — Status "blocked" basi setelah izin diberikan
- **Laporan owner (2026-09-09, screenshot)**: notifikasi status "Alerts blocked by system settings" tetap tampil meski izin notifikasi sudah diberikan.
- **Diagnosis (terverifikasi di kode)**:
  1. Snapshot basi (primer): `systemState` hanya di-refresh di `onAppForegrounded()` yang dipicu `LifecycleStartEffect` = ON_START (`AppRoot.kt:50`). Dialog izin sistem hanya mem-pause activity (tanpa stop), jadi grant via Settings in-app tidak memicu ON_START — snapshot `notificationsPermitted=false` bertahan. Emisi collector berikutnya (sync timestamp, bahasa, toggle) mem-posting ulang notifikasi "blocked" padahal izin sudah ada (`AppViewModel.kt:125-133, 168-194`).
  2. Cek sempit (sekunder): `canPostNotifications()` (`device/DeliveryPrerequisites.kt:30`) hanya cek runtime permission `POST_NOTIFICATIONS` — tidak mendeteksi toggle app-level dimatikan (`areNotificationsEnabled`) maupun channel di-set NONE. Arah berlawanan (lapor "aktif" padahal tak bisa masuk) tapi satu area yang sama.
- **Audit Hermes 2026-09-09 (terverifikasi di kode)**:
  1. Dua pembaca, dua kadensi: Settings UI refresh tiap ON_RESUME (`SettingsScreen.kt:117` + `refreshSystemState()`) sehingga selalu benar; notifikasi status hanya ON_START (`AppRoot.kt:50` `LifecycleStartEffect` → `AppViewModel.onAppForegrounded`). Dialog izin runtime tidak memicu ON_START → snapshot basi `false` + emisi collector berikutnya mem-posting "blocked" meski izin sudah ada. Cocok dengan gejala.
  2. `canPostNotifications()` (`DeliveryPrerequisites.kt:30`) buta terhadap toggle app-level dan channel NONE. Blast radius perubahan semantik: `AlertRaiser:133` (gate local-test), `AppViewModel` x2, `SettingsViewModel` x3, `WarningViewModel:108`.
  3. Preseden `AlertPresentationHealth`: degradasi channel-level bersifat diagnostik, tidak pernah jadi gate — perbaikan tidak boleh melipat importance channel ke dalam gate.
  4. Test: hanya JVM murni (copy + toggle flow); `DeliveryPrerequisites` butuh Context → tidak ada permukaan baru yang unit-testable, verifikasi manual wajib.
- **D-021 (DISETUJUI owner 2026-09-09, tercatat di `docs/DECISIONS.md`)**: "Notifikasi status membaca ulang grant OS di setiap resume, dan 'boleh posting' berarti runtime grant + toggle app-level." Isi: (F1) `LifecycleResumeEffect` di `AppRoot` → refresh `systemState` (syncIfStale tetap terjaga guard-nya); (F2) `canPostNotifications()` → `NotificationManagerCompat.areNotificationsEnabled()` + update KDoc; channel tetap diagnostik. Verifikasi: grant via dialog in-app → status flip tanpa backgrounding; toggle app-level off/on di system settings → flip blocked/active; suite unit + lint hijau.
- **Syarat lanjut**: implementasi oleh OpenCode.

### P-LANG-SYSTEM — Bahasa aplikasi mengikuti bahasa HP
- **Keputusan owner (2026-09-09)**: bahasa aplikasi default mengikuti bahasa HP — HP Indonesia → Indonesia, selain itu → Inggris. Pilihan eksplisit user di Settings tetap menang atas default sistem.
- **Audit Hermes 2026-09-09 (terverifikasi di kode)**:
  1. Resolver tidak perlu diubah: `resolveDisplayLanguage(null)` sudah ikut `Locale.getDefault()` dan sudah diuji (`DisplayLanguageTest`: null/empty/unknown → sistem, EN terakhir). Yang mematikan cabang sistem hanya default `"en"` repository.
  2. Permukaan perubahan mekanis: `AppSettingsRepository.language` → `Flow<String?>` (null = System, hapus `DEFAULT_LANGUAGE`); ~10 call-site `.map { resolveDisplayLanguage(it) }` sudah menerima nullable (nol logika berubah); one-shot `first()` di service sudah toleran null. `AppLanguage` + entri SYSTEM (tag null); `fromTag(String?)`: null → SYSTEM, unknown → EN (tetap).
  3. Tanpa AppCompat di proyek (hanya core-ktx): cermin pilihan eksplisit ke system settings HP via framework `LocaleManager.setApplicationLocales()` (API 33+, version-guard); <33 in-app saja. Tanpa dependensi baru.
  4. Background/service (`AlertRaiser`, `QuakeMessagingService`, `BackgroundAlertBridge`) sudah resolve via `resolveDisplayLanguage(stored)` → ikut otomatis, tanpa campuran bahasa.
  5. Migrasi: instalasi lama tersimpan "en" = eksplisit EN (pra-rilis, diterima). Segmented Settings 2→3 opsi + label SYSTEM ("System", fixed seperti "EN"/"ID").
- **D-022 (DISETUJUI owner 2026-09-09, tercatat di `docs/DECISIONS.md`)**: "Bahasa default = System (null tersimpan); HP Indonesia → ID, lainnya EN; pilihan eksplisit menang dan dicerminkan ke `LocaleManager` di API 33+." Verifikasi: locale ID → ID otomatis; locale lain → EN; ganti bahasa HP → ikut setelah recreate; pilihan eksplisit tidak tertimpa; suite unit + lint hijau.
- **Syarat lanjut**: implementasi oleh OpenCode.
